# web/: React frontend

**Before any UI work, use the `lingolab-design` skill.** It is the design source of truth; the `shadcn` skill covers component usage.

## Stack (don't swap libraries without asking)

| Concern | Library | Notes |
|---|---|---|
| Build | Vite + `@vitejs/plugin-react` | SPA. No SSR, no Next.js |
| Language | TypeScript, `strict: true` | No `any`; use `unknown` and narrow |
| Routing | TanStack Router, file-based (`src/routes/`) | Mirror legacy SvelteKit paths 1:1 |
| Server state | TanStack Query | All API data goes through Query |
| API client | `openapi-fetch` + `openapi-react-query` | Types come from `src/api/schema.d.ts` (generated) |
| Realtime | `socket.io-client` | Wrapped in `src/realtime/` with typed events |
| Client state | Zustand | Only for live game/lobby state, nothing else |
| Forms | `react-hook-form` + `zod` | Replaces felte + yup |
| UI | shadcn/ui + Tailwind CSS v4 + `lucide-react` | Add components via the shadcn MCP/CLI; don't hand-write primitives |
| i18n | `i18next` + `react-i18next` | **Reuse the legacy translation keys** |
| Unit tests | Vitest + Testing Library + MSW | |
| E2E | Playwright (`@playwright/test`) | Automated tests only; interactive checks use the `brave-devtools` MCP |
| Lint/format | Biome | |

Always check current docs through the Context7 MCP before using an API you are unsure about.
Library versions change quickly; don't rely on memory.

## Directory structure

```
web/src/
  api/
    schema.d.ts        # GENERATED by `pnpm gen:api`. Never edit by hand
    client.ts          # openapi-fetch + openapi-react-query instances (credentials: 'include')
  realtime/
    socket.ts          # single socket.io instance, connect/disconnect helpers
    events.ts          # typed ServerToClient / ClientToServer event maps
  routes/              # TanStack file routes, mirroring frontend/src/routes
  features/<area>/     # components + hooks per area: auth, dashboard, editor, play, host, results, ...
  components/ui/       # shadcn components (generated, fine to tweak)
  components/          # shared app components (Navbar, Footer, LanguageToggle, ...)
  lib/                 # framework-agnostic helpers ported from frontend/src/lib (hashcash, helpers, ...)
  locales/<lang>.json  # copied from frontend/src/lib/i18n/locales, same keys
  config.ts            # app name, feature flags
```

## Key facts about the backend

- **Auth:** the backend sets an httpOnly `access_token` cookie. The frontend cannot read it.
  To find out who is logged in, call `GET /api/v1/users/check`; it returns the email or fails, and refreshes the cookie.
  This replaces legacy `hooks.server.ts` and the `+layout.server.ts` files. Protected routes use a `beforeLoad` guard that
  redirects to `/account/login?returnTo=<path>`.
- All fetches use `credentials: 'include'` and relative URLs (`/api/...`). In dev, Vite proxies to `:8000`.
- The OpenAPI spec is at `/openapi.json`. **Socket.IO events are not in it.** Derive them from
  `classquiz/socket_server/__init__.py`, `SocketIo.md` and `frontend/src/lib/socket.ts`, and keep `realtime/events.ts` up to date.
- The backend runs with a single worker (live game state is in Redis). Don't design anything that assumes horizontal scaling.

## Translating legacy SvelteKit patterns

| Legacy | New |
|---|---|
| `+page.server.ts` redirect when logged out | route `beforeLoad` auth guard |
| `+page.ts` / `load()` | route `loader` with `queryClient.ensureQueryData` |
| Svelte stores / `stores.svelte.ts` | Query cache (server data) or Zustand (live game) |
| `$page.url.searchParams` | typed `validateSearch` with zod |
| `onMount` / `browser` checks | `useEffect`. No SSR, so no browser checks needed |
| `felte` + `yup` (`yupSchemas.ts`) | `react-hook-form` + `zod` (port the schemas) |
| `ckeditor5` (GPL!) | Tiptap |
| `sortablejs` | `@dnd-kit` |
| `svelte-tippy` / `tippy.js` | shadcn Tooltip / Popover |
| `swiper` | shadcn Carousel (Embla) |
| `svelte-range-slider-pips` | shadcn Slider |
| `@uppy/svelte` | `@uppy/react` or a simple custom dropzone (ask first) |
| `qrcode` | `qrcode.react` |
| `marked`, `dompurify`, `highlight.js`, `canvas-confetti`, `@simplewebauthn/browser`, `thumbhash`, `luxon` | keep as-is |

## Conventions

- Function components with named exports, one component per file, `PascalCase.tsx`.
- Every data view handles **loading, error and empty** states.
- Mobile-first: students play on phones. The host screen (`/admin`) targets a projector (large type, high contrast).
- Accessibility: every input has a label, all actions work with the keyboard, colour is never the only signal
  (answer tiles need shape/icon + colour).
- Dark mode supported through shadcn theming (legacy app had it).
- Use `t('key')` with the **same keys** as the legacy component. If you need a new key, add it to `locales/en.json` and `locales/de.json`.
- No hardcoded user-facing strings.

## Definition of done (per route)

1. Behaviour matches the legacy route (inventory checklist in the PR is complete).
2. `pnpm typecheck && pnpm lint && pnpm test` pass.
3. At least one Playwright e2e test covers the main flow.
4. Verified in the browser through the `brave-devtools` MCP at `http://localhost:5173`: screenshots in light and dark mode,
   mobile (390px) and desktop width, no console errors, no failed network requests, accessibility tree checked.
5. Follows the `lingolab-design` skill (tokens only, no raw hex, contrast rules).
6. `MIGRATION.md` item ticked.
