## Goal

Port the public page of a single quiz. It shows the title, author, cover image, stats and like/dislike rating,
the actions (start game, practice, download, report) and every question with its answers. Until then `/view/$quizId`
was a "coming soon" placeholder. Bruno's instruction was "lets get started on the next PR"; the handoff memory
named PR 11 `/view/[quiz_id]` as next, and the scope came from the Phase 2 breakdown in `MIGRATION.md`.

## What happened

1. **Inventory.** Claude read the six legacy files (`+page.server.ts`, `+page.svelte`, `ModComponent.svelte` and
   `lib/view_quiz/*`, 679 lines in total, much of it inline SVG icons) plus `lib/collapsible.svelte`. The total is above
   the skill's ~400-line split threshold. No split was proposed, because `MIGRATION.md` already planned the route
   as one PR. The inventory became the body of PR #31.
2. **Checking the backend.** The generated API types leave the public quiz response as `unknown`. Claude called
   `GET /api/v1/quiz/get/public/{id}` on the running dev backend with `curl` for a public quiz, a private quiz and a
   malformed id. The results:
   - The response shape (author as `{id, username}`, counters as numbers) matched the backend model.
   - A **private** quiz was returned with status 200: the endpoint does not check the `public` flag.
   - A malformed id gave 422, which legacy's loader would have shown as a server error.
   - Reading the endpoint's code showed that **every request adds one view**.

   No backend change was made (rewrite-phase rule); the private-quiz finding is logged as a Legacy quirk.
3. **Findings that shaped the port** (all logged in `MIGRATION.md`):
   - The "Report" link mails `report@mawoka.eu`, the upstream author's address, from every deployment.
   - Like/dislike are offered when signed out; the backend answers 401 and nothing visible happens. When a
     signed-in user switches a vote, legacy only adds the new vote locally, although the backend moves it.
   - Right and wrong answers differ only by a blue or yellow shadow (colour as the only signal).
   - Tooltips, the RANGE sentence, the moderation labels and an error message are hardcoded English, and a
     moderation label is misspelt ("NFSW").
   - The legacy "Practice" button links to `/practice`, a route not yet registered in `web/` (Phase 3).
4. **Implementation** (by Claude), in `web/src/features/view/` unless noted:
   - `viewApi.ts` parses the response with zod, maps 400/404/422 to "not found", and holds the rating and
     moderation calls. Because each request counts a view, the query is fetched once per visit and is never
     refetched on window focus or reconnect.
   - Components: `ViewQuizPage.tsx` (loading, not-found and error states), `QuizRating.tsx`, `ImportedBadge.tsx`,
     `ModerationPanel.tsx` (a labelled radio group instead of legacy's dimming buttons) and `QuestionPreview.tsx`
     (one collapsible section per question; right answers get a check mark and screen-reader text; slides go through
     the shared `SlideRenderer` from PR #21, question text through `RichText` from PR #19).
   - Reuse outside the feature folder: `StartGameDialog` (dashboard) now accepts any `{id, title}` and a `returnTo`
     for an expired session. `DownloadQuizDialog` and `MediaComponent` are reused unchanged.
   - New: shadcn `Collapsible`; the config value `reportEmail` (from `VITE_REPORT_EMAIL`, link hidden when unset);
     a `/practice` placeholder route; 32 new `view_quiz_page.*` keys (en + de).
5. **Dead ends during the build.**
   - The first version wrapped disabled buttons in a focusable `<span>` so that their tooltip could explain why.
     Biome rejected the `aria-label` on the span. Claude replaced the wrapper with `aria-disabled` on the buttons
     themselves, which keeps them focusable and lets the tooltip attach directly.
   - A custom retry rule on the quiz query made the "load failed" test time out (retries with delay). It was
     removed; the app's default retry applies.
   - Component tests failed because jsdom has no `ResizeObserver` (used by Radix tooltips and radios); the test
     file stubs it, as two earlier test files already do.
   - The first e2e run failed because Playwright's name match for "Like this quiz!" also matched "Dislike this
     quiz!"; the test now uses an exact match.
6. **Visual check on the real backend.** Unlike PRs 9 and 10, the page was checked with `brave-devtools` against
   the running dev backend (signed out), at 390 and 1280 px in light and dark mode. The only console error was the
   expected 401 from the signed-out session check. The view counter went from 59 to 60 with one page load,
   confirming one request per visit. On the private "Legacy slide fixture" quiz with `?mod=1`, the rating card
   stretched to the height of the moderation panel (screenshot 2). Claude fixed this with one class
   (`items-start`); screenshot 3 shows the result.
7. **git blocked by iCloud.** When updating `MIGRATION.md`, `git diff` and `git status` (even with `-uno`) hung, as
   did a repo-wide `grep`. Claude found 106 "dataless" files in the repo, including loose objects in
   `.git/objects`: the repo lives on the iCloud-synced Desktop, and iCloud had evicted them. `brctl download .`
   returned successfully, but no file was downloaded within a minute. Claude stopped, reported the problem with
   three possible remedies, and saved it to its memory. When Bruno asked to retry, `git status` worked (105 files
   were still dataless, none of them needed). Claude committed `53704b9`, pushed and opened PR #31.

## Observations for the thesis

- **Licensing and privacy surfaced through a link.** The Report link was a small piece of markup, but in a fork it
  sent every report from every school's deployment to the upstream author. Forks inherit such hardcoded
  operator details; parity cannot simply copy them.
- **A side effect in a read endpoint.** Because a GET counts a view, the client's caching settings decide whether
  the statistics a teacher sees are correct. The legacy app loaded the quiz on the server once per page load. A
  default client setup would have refetched it on every focus. The real backend check (59 → 60) was the
  evidence that the setting worked.
- **The development environment as a source of failure.** The iCloud eviction had nothing to do with the code,
  but it stopped the workflow: commands hung silently instead of failing. Diagnosing it took several steps
  (timeouts, process list, `find -flags +dataless`). It was left to Bruno, because the remedies (sync settings,
  moving the repo) are his decisions.
- **Display and access fixes again decided by the AI.** As in PRs 8–10, the deviations listed above were judged
  and logged by Claude, not specified by Bruno beforehand. TODO(Bruno): whether the rating change (disabled when
  signed out, corrected counts) counts as a behaviour change under the parity rule.
